# 🧩 Каталог Ompra

[English](README.md) · **Українська**

**Куровані плагіни та навички для вашого робочого простору Ompra.**

[![Ліцензія: MIT](https://img.shields.io/badge/license-MIT-64748b?style=flat-square)](LICENSE)
[![Каталог: окремі оновлення](https://img.shields.io/badge/catalog-independent_updates-64748b?style=flat-square)](#updates)

Курований каталог плагінів і навичок для **Ompra**, який оновлюється окремо від
десктопного застосунку. **Каталог 1.1.2 містить 22 картки: 16 віддалених
MCP-конекторів і шість власних навичок Ompra.** Версії застосунку з підтримкою
віддаленого каталогу можуть завантажити цю добірку без заміни EXE.

- **Свіжа добірка** — нові описи та рекомендації без перевипуску застосунку.
- **Контроль установлення** — користувач підтверджує встановлення й оновлення пакетів.
- **Робота без мережі** — доступна остання збережена копія або вбудована добірка.

## 🚀 Швидкий старт

У версії Ompra з підтримкою віддаленого каталогу:

1. Відкрийте **Settings → Plugins → Sources** і виберіть каталог за замовчуванням.
2. Натисніть **Refresh catalog** та перегляньте доступні картки плагінів.
3. Онлайн-добірка має показати **22 картки**. Виберіть плагін і підтвердьте його
   встановлення.
4. Для конектора з авторизацією виконайте кроки [підключення облікового запису](#connect-account).

**Ompra вже встановлено?** Оновіть віддалений каталог у поточному застосунку;
для завантаження цих карток новий EXE не потрібен. Якщо досі видно лише шість
навичок, перевірте **Sources**: вбудована офлайн-добірка чи власна адреса не
перемикаються на поточний каталог GitHub автоматично. Виберіть онлайн-джерело
за замовчуванням, підтвердьте його підключення за потреби та оновіть каталог.
За помилки мережі застосунок може залишити останню збережену добірку.

Для ручного підключення використовуйте цю **адресу вітрини**:

```text
https://raw.githubusercontent.com/vallgrice/ompra-catalog/main/catalog.json
```

Для завантаження пакетів потрібні **Git та інтернет**. Окремий обліковий запис
GitHub або токен користувачеві не потрібні. Для відповідей агента використовується
провайдер, налаштований в Ompra.

| Джерело | Призначення |
|---|---|
| [Вітрина каталогу](https://raw.githubusercontent.com/vallgrice/ompra-catalog/main/catalog.json) | Назви, описи, вимоги та приклади запитів, які відображаються в Ompra |
| [Оформлення вітрини](presentation.json) | Тематичні розділи, їхній порядок та ідентифікатори підтримуваних логотипів |
| [Маркетплейс OMP](https://raw.githubusercontent.com/vallgrice/ompra-catalog/main/.omp-plugin/marketplace.json) | Версії пакетів та незмінні джерела встановлення |

### 🎨 Перегляд за темами

Оновлена вітрина розподіляє всі 22 картки за шістьма темами: **розробка**,
**документи й дані**, **проєкти й команда**, **пошук і веб**, **бізнес і аналітика**,
**навички для коду**. Натисніть заголовок розділу, щоб відкрити його окремо, або
шукайте в усьому каталозі. Airtable розміщено в розділі **документи й дані**.

Логотипи сервісів відображаються в каталозі, деталях плагіна та бічному списку
встановлених. SVG-файли входять до застосунку: показ іконок не потребує запитів
до сторонніх сервісів зображень. Навички мають окремі кольорові іконки.
Підтримуються світла й темна теми.

**Для нового вигляду та логотипів потрібна оновлена десктопна збірка.** Старі
версії й надалі можуть завантажувати всі 22 картки завдяки незмінному формату V1.
Сумісні збірки також читають `presentation.json` із цього репозиторію та зберігають
останню робочу копію для роботи без мережі. Назви, порядок і склад розділів надалі
можна змінювати тут без заміни застосунку.

Версії Ompra з підтримкою віддаленого каталогу використовують цю вітрину за
замовчуванням. Під час відкриття одразу відображається збережена копія, а потім
перевіряються оновлення на GitHub. Без мережі залишається остання робоча копія або
вбудована добірка. У **Settings → Plugins → Sources** можна вказати власну адресу,
повернути джерело за замовчуванням або вибрати вбудовану добірку для роботи без мережі.

> **Оновлення списку не оновлює код установлених плагінів.** Установлення та
> **Update** виконуються лише після підтвердження.

Якщо раніше встановлено вбудовану добірку `ompra-starter`, кнопка підключення
джерела переводить її на цей маркетплейс зі збереженням ID та встановлених пакетів.
Під час підключення код пакетів, їхні налаштування та стан увімкнення не змінюються.

## 🔌 Доступні конектори

Це справжні пакети Agent Plugins для встановлення, з кореневими `plugin.json` і
`mcp.json`, закріплені за незмінними Git-комітами. Вони підключають віддалені
HTTP-сервіси; Node, Python, браузери та код серверів постачальників до пакетів
не входять.

| Конектор | Призначення | Перше підключення |
|---|---|---|
| 📚 Context7 | Документація бібліотек і приклади | Обмежений режим без ключа |
| 🔎 Firecrawl | Вебпошук, вміст сторінок і розбір файлів | Обмежений режим без ключа |
| 🗂️ [Airtable](docs/AIRTABLE.md) | Бази, записи, схеми й підтримувані чернетки автоматизацій | OAuth у браузері |
| 📝 Notion | Сторінки, бази даних і знання робочого простору | OAuth у браузері |
| 📋 Linear | Задачі, проєкти й коментарі | OAuth у браузері |
| 🗄️ Supabase | Структура бази даних і діагностика проєкту | OAuth; пакет використовує режим читання |
| 🔗 Atlassian | Jira та Confluence | OAuth; діють політики організації |
| 🐛 Sentry | Помилки застосунку та діагностика | OAuth у браузері |
| 🛫 Plane | Робочі задачі, проєкти й цикли | OAuth у браузері |
| 🧾 Jotform | Форми та відповіді користувачів | OAuth у браузері |
| 📊 PostHog | Продуктова аналітика та прапорці функцій | OAuth у браузері |
| 🚆 Railway | Сервіси, проєкти й контекст розгортань | OAuth у браузері |
| 💳 Stripe | Контекст платежів і підписок | OAuth у браузері |
| 🌐 Exa | Вебпошук і вміст сторінок | Обмежений режим без ключа; явний додатковий інструмент обходить фільтр OMP для суто вбудованих функцій |
| 🐙 GitHub | Репозиторії, issues, PR і Actions | Локальне налаштування особистого токена |
| ☁️ Render | Сервіси, розгортання, журнали та метрики | Локальне налаштування API-ключа |

Для режимів без ключа діють ліміти сервісів. Згода OAuth, дозволи, вибрані ресурси,
тарифи й адміністративні політики визначаються постачальником. MIT стосується
наших визначень конекторів, а не хмарних SaaS-сервісів. Наявність пакета не означає
офіційного схвалення Ompra постачальником.

<a id="connect-account"></a>

## 🔐 Підключення облікового запису

### OAuth у браузері

1. Установіть конектор і дозвольте Ompra перезавантажити плагіни за потреби.
2. У нових збірках Ompra залишайтеся на сторінці плагіна та натисніть
   **Applications → Connect → Open browser**. Очікування авторизації, скасування,
   повторне підключення й ручне введення коду доступні тут само. У старих збірках
   відкрийте **Settings → MCP**, знайдіть **`<package>:api`** — наприклад,
   **`airtable:api`** — та виберіть **Reauthorize** в меню сервера.
3. Надайте згоду у браузері постачальника й виберіть доступні для конектора ресурси.
4. Поверніться до Ompra, дочекайтеся підключення та перевірте стан і кількість
   інструментів. Почніть із безпечного запиту на читання.

**Установлено ≠ підключено.** Пакет може бути встановленим, тоді як його сервер
відключений, має нуль інструментів або очікує авторизації. До першого входу деякі
виявлені сервери також не показують позначку авторизації. Стан установлення не
підтверджує підключення облікового запису.

### GitHub і Render: локальний ключ

Пакети не містять облікових даних. Після встановлення додайте MCP-сервер зі
сферою **User** та точною назвою **`github:api`** або **`render:api`**.
Виберіть HTTP і вкажіть:

| Конектор | Адреса | Локальний заголовок |
|---|---|---|
| GitHub | `https://api.githubcopilot.com/mcp/` | `Authorization`: `Bearer `, а після нього — ваш PAT |
| Render | `https://mcp.render.com/mcp` | `Authorization`: `Bearer `, а після нього — ваш API-ключ |

Локальний запис замінює визначення підключення з пакета. Вибирайте лише потрібні
дозволи. Вводьте справжній ключ локально: стандартні заголовки пакета не
підставляють `${TOKEN}`. Ключ зберігається в локальній MCP-конфігурації; це не
гарантія зберігання в системному сховищі секретів. Не додавайте його до Git,
репозиторію чи звітів. Для такого запису використовуйте підключення за ключем,
а не **Reauthorize**.

> **Видалення пакета не видаляє окремий запис User.** Також видаліть цей
> MCP-запис, якщо більше не хочете мати доступ до його інструментів. Ключ або
> OAuth-доступ відкликайте окремо на стороні постачальника.

Для серверів із плагінів кнопка **Test** у закріпленій версії рушія може
повідомляти «Server not found», хоча сервер виявлено. Перевіряйте стан підключення
та кількість інструментів; саме це повідомлення не доводить помилку авторизації.

## 🗺️ Добірка та плани

Розширена [добірка за зразком каталогу OpenAI](CURATED.md) містить **35 карток на
базі 29 інтеграцій**, включно з Airtable, першоджерела, вимоги й стан публікації.
**Шістнадцять конекторів є в каталозі для встановлення; решту ще не можна
встановити.** Сім карток Google описують один запланований Workspace-конектор
спільноти. Шість початкових навичок враховані в каталозі застосунку, а не в цій
дослідницькій добірці. Документ написано російською; машинна версія доступна в
[curation.json](curation.json).

> Застосунок читає **`catalog.json`**, а не `curation.json`. Публікація дослідження
> або README не додає картки в Ompra. Для нової картки потрібен справжній пакет
> та оновлення обох індексів установлення.

плагін, перевірте сумісність з OMP, ліцензію, підтримувані платформи, фактичні
залежності та спосіб авторизації. Не публікуйте ключі, токени та приватні адреси.

<a id="updates"></a>

## 🔄 Оновлення

### Зміни метаданих

Якщо змінюються лише описи, достатньо відредагувати `catalog.json`, збільшити версію
каталогу й оновити `updatedAt`, виконати перевірку та надіслати коміт до `main`.

Для зміни розділів відредагуйте `presentation.json`: назви, порядок та `pluginIds`,
після чого збільште його власну `version`. Зберігайте ID плагінів і розміщуйте кожну
опубліковану картку в одному розділі. Поле `brands` приймає лише ідентифікатори
логотипів, що входять до застосунку; довільні адреси зображень і виконуваний вміст
відхиляються. Для нового SVG-логотипа потрібна нова десктопна збірка. Перед
публікацією виконайте `npm run check`; **Refresh catalog** у сумісній збірці
оновлює обидва файли метаданих.

### Зміни пакетів

1. Відредагуйте навичку чи MCP-визначення та збільште `version` у `plugin.json` і `package.json`,
   зокрема вкладене поле `omp.version` у `package.json`.
2. Створіть коміт пакетів. Повний SHA цього коміту буде джерелом нової версії.
3. Для MCP-добірки оновіть метадані карток у `connectors.json` та виконайте
   `node scripts/publish-index.mjs <packageSHA> <catalogVersion>`, замінивши
   `<packageSHA>` повним SHA з кроку 2, а `<catalogVersion>` — наступною версією
   каталогу (наприклад, `1.2.0`). Скрипт звіряє вміст пакетів із комітом
   і записує обидва індекси.
   Для зміни навички оновіть версію та `source.sha` у маркетплейсі вручну;
   джерело `git-subdir` вказує на `plugins/<name>`.
4. Перевірте узгодженість версій пакетів, версію каталогу та `updatedAt`.
   Для навички також потрібна відповідна версія в `catalog.json`.
5. Виконайте `npm run check`, створіть коміт індексів і документації та надішліть обидва
   коміти до `main`. Не підмінюйте вміст уже опублікованої версії пакета.
6. В Ompra натисніть **Refresh catalog**, перевірте картку та підтвердьте **Update**.

SHA закріплює вміст пакета незалежно від подальших змін гілки.
Адреси вітрини та маркетплейсу залишаються сталими.

<a id="validation"></a>

## ✅ Перевірка

```sh
npm run check
```

Скрипт перевіряє узгодженість двох індексів і локальних пакетів, незмінні
Git-посилання, ліцензії та обов'язкові переклади. Ompra додатково перевіряє
завантажений JSON за повною схемою перед відображенням і збереженням.
Той самий валідатор можна запустити безпосередньо: `node scripts/validate.mjs`.

[Перевірки без авторизації](research/remote-probes.json) підтвердили `initialize`
і `tools/list` для Context7, Firecrawl та Exa в режимі без ключа. Метадані OAuth
оголошують підтримку DCR для 11 конекторів з основним входом через OAuth;
[результати Airtable](research/airtable.json) збережено окремо. Ці перевірки не
виконують згоду облікового запису, обмін токенів або виклик інструмента сервісу.
Авторизований доступ і операції запису не заявляються як перевірені. Валідація
каталогу не є сертифікацією безпеки.

Механізм локального запису User та його збереження після видалення пакета
перевірено у вбудованому OMP зі штучним тестовим сервером. Це перевірка локальної
конфігурації, а не авторизації облікового запису GitHub або Render.

В окремому нативному запуску пройшли 32 цільові перевірки вбудованого `omp.exe`,
зокрема встановлення з публічного GitHub-коміту. Рушій установив усі 16 MCP-пакетів і
виявив їх як сервери. Тести підключення повернули 2 інструменти Context7,
3 Firecrawl і 2 Exa. Через скомпільований OMP виконано один справжній публічний
пошук бібліотеки React у Context7, із локальною заглушкою моделі та без справжнього
ключа модельного провайдера. Вибрані сценарії ввімкнення, вимкнення та видалення
також пройшли. Ця перевірка не підтверджує авторизований OAuth-доступ до сервісів
з обліковими записами.
Дивіться [підсумок нативної перевірки](research/native-validation.json) із хешем
рушія, комітом пакетів та межами перевірки.
