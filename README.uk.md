# 🧩 Каталог Ompra

[English](README.md) · **Українська**

**Куровані плагіни та навички для вашого робочого простору Ompra.**

[![Ліцензія: MIT](https://img.shields.io/badge/license-MIT-64748b?style=flat-square)](LICENSE)
[![Каталог: окремі оновлення](https://img.shields.io/badge/catalog-independent_updates-64748b?style=flat-square)](#updates)

Курований каталог плагінів і навичок для **Ompra**, який оновлюється окремо від
десктопного застосунку. Початкова добірка містить шість навичок для щоденної роботи
з кодом.

- **Свіжа добірка** — нові описи та рекомендації без перевипуску застосунку.
- **Контроль установлення** — користувач підтверджує встановлення й оновлення пакетів.
- **Робота без мережі** — доступна остання збережена копія або вбудована добірка.

## 🚀 Швидкий старт

У версії Ompra з підтримкою віддаленого каталогу:

1. Відкрийте **Settings → Plugins → Sources** і виберіть каталог за замовчуванням.
2. Натисніть **Refresh catalog** та перегляньте доступні картки плагінів.
3. Виберіть плагін і підтвердьте його встановлення.

Для ручного підключення використовуйте цю **адресу вітрини**:

```text
https://raw.githubusercontent.com/vallgrice/ompra-catalog/main/catalog.json
```

Для завантаження пакетів потрібні **Git та інтернет**. Окремий обліковий запис
GitHub або токен користувачеві не потрібні. Для відповідей агента використовується
провайдер, налаштований в Ompra.

| Джерело | Призначення |
|---|---|
| [Вітрина каталогу](https://raw.githubusercontent.com/vallgrice/ompra-catalog/main/catalog.json) | Назви, описи, вимоги та приклади запитів, які відображаються в Ompra |
| [Маркетплейс OMP](https://raw.githubusercontent.com/vallgrice/ompra-catalog/main/.omp-plugin/marketplace.json) | Версії пакетів та незмінні джерела встановлення |

Версії Ompra з підтримкою віддаленого каталогу використовують цю вітрину за
замовчуванням. Під час відкриття одразу відображається збережена копія, а потім
перевіряються оновлення на GitHub. Без мережі залишається остання робоча копія або
вбудована добірка. У **Settings → Plugins → Sources** можна вказати власну адресу,
повернути джерело за замовчуванням або вибрати вбудовану добірку для роботи без мережі.

> **Оновлення списку не оновлює код установлених плагінів.** Установлення та
> **Update** виконуються лише після підтвердження.

Якщо раніше встановлено вбудовану добірку `ompra-starter`, кнопка підключення
джерела переводить її на цей маркетплейс зі збереженням ID та встановлених пакетів.
Під час підключення код пакетів, їхні налаштування та стан увімкнення не змінюються.

## 🧰 Початкова добірка

| Пакет | Навичка | Призначення |
|---|---|---|
| 👀 `review` | `ompra-review` | Перегляд змін і перевірка регресій |
| 🧪 `testing` | `ompra-testing` | Тестування спостережуваної поведінки |
| 🐛 `debugging` | `ompra-debugging` | Пошук і перевірка першопричини помилки |
| 🧹 `refactoring` | `ompra-refactoring` | Рефакторинг зі збереженням поведінки |
| 📚 `documentation` | `ompra-documentation` | Документація на основі поточного коду |
| 🛡️ `security` | `ompra-security` | Перевірка меж довіри та можливих шляхів зловживання |

Це текстові інструкції без виконуваних хуків і додаткових npm-залежностей.
Перевірка структури не є сертифікацією безпеки або якості відповідей моделі.

<a id="planned-integrations"></a>

## 🗺️ Заплановані інтеграції

Розширена [добірка за зразком каталогу OpenAI](CURATED.md) містить **34 запропоновані
картки на базі 28 інтеграцій**, першоджерела, вимоги до підключення та пріоритети.
Документ написано російською; машинна версія доступна в [curation.json](curation.json).

Це **дослідницька чернетка**, а не список установлених чи готових до встановлення
плагінів. До каталогу для встановлення потрапляють лише пакети, які пройшли
перевірку сумісності та підключення.

<a id="maintaining"></a>

## 🛠️ Підтримка каталогу

| Файл | Що містить |
|---|---|
| [catalog.json](catalog.json) | Назви, описи, вимоги, посилання та приклади запитів у вітрині |
| [.omp-plugin/marketplace.json](.omp-plugin/marketplace.json) | Фактичні версії пакетів та джерела встановлення OMP |
| `plugins/<name>/skills/ompra-<name>/SKILL.md` | Вміст власної навички |
| [curation.json](curation.json) та [research/](research/) | Заплановані інтеграції та дослідження; окремо від джерел установлення |

Назви `ompra-starter`, пакетів і навичок зберігаються між оновленнями.
Не використовуйте наявний ID для іншого автора або продукту. Додаючи сторонній
плагін, перевірте сумісність з OMP, ліцензію, підтримувані платформи, фактичні
залежності та спосіб авторизації. Не публікуйте ключі, токени та приватні адреси.

<a id="updates"></a>

## 🔄 Оновлення

### Зміни метаданих

Якщо змінюються лише описи, достатньо відредагувати `catalog.json`, збільшити версію
каталогу й оновити `updatedAt`, виконати перевірку та надіслати коміт до `main`.

### Зміни навичок

1. Відредагуйте `SKILL.md` та збільште `version` у `plugin.json` і `package.json`,
   зокрема вкладене поле `omp.version` у `package.json`.
2. Створіть коміт пакетів. Повний SHA цього коміту буде джерелом нової версії.
3. У `.omp-plugin/marketplace.json` змініть версію та `source.sha` відповідного
   пакета на SHA з кроку 2. Джерело `git-subdir` вказує на `plugins/<name>`.
4. Узгодьте версію пакета в `catalog.json`, збільште версію каталогу й оновіть `updatedAt`.
5. Виконайте `node scripts/validate.mjs`, створіть коміт індексу та надішліть обидва
   коміти до `main`. Не підмінюйте вміст уже опублікованої версії пакета.
6. В Ompra натисніть **Refresh catalog**, перевірте картку та підтвердьте **Update**.

SHA закріплює вміст пакета незалежно від подальших змін гілки.
Адреси вітрини та маркетплейсу залишаються сталими.

<a id="validation"></a>

## ✅ Перевірка

```sh
node scripts/validate.mjs
```

Скрипт перевіряє узгодженість двох індексів і локальних пакетів, незмінні
Git-посилання, ліцензії та обов'язкові переклади. Ompra додатково перевіряє
завантажений JSON за повною схемою перед відображенням і збереженням.
