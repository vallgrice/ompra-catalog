# Project documentation

Write for the reader's actual task and support every technical claim with the repository or verified primary documentation.

1. Identify the audience and the document's purpose: installation, first use, troubleshooting, configuration, or API reference.
2. Inspect the implementation, package scripts, supported platforms, configuration schema, and existing documentation. Preserve license and author attribution.
3. Describe the current behavior. Do not present planned features, unverified platforms, or hypothetical examples as working functionality.
4. Use concise headings, copyable commands, realistic examples, expected outputs, and clear prerequisites. Keep secrets out of examples and use obvious placeholders when authentication is required.
5. Check commands in an isolated environment when practical and within scope. Verify local file references and distinguish commands actually run from examples only inspected.
6. Update related references and translations when the project requires them. Avoid duplicating information that has a clear existing source.

Do not publish documentation or push changes unless the user authorized publication. If an external fact cannot be verified, either omit it or state the uncertainty.

## Deliverable

Provide the updated document and briefly identify checked examples, unresolved prerequisites, and any limits in verification.
